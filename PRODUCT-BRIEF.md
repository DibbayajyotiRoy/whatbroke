# whatbroke: Grounded, Secret-Free Crash Context for the Local Terminal

whatbroke is a local-only CLI and library that wraps a developer command (`whatbroke run -- npm test`) and, when that command crashes, packages everything needed to understand and reproduce the failure into a redacted bundle that a coding agent can read over a local MCP server. It diagnoses; it does not fix. Its defensible core is deterministic, not generative: a per-clone green-commit journal crossed with the crash stack trace to rank the file most likely at fault, with zero LLM involvement. v1 is Node/TS only. There is no backend, no account, and no dashboard.

## Executive Summary

- **The pain is acute and momentary.** When a Node/TS suite or server crashes in the terminal, the developer must hand-reassemble the stack trace, uncommitted diff, versions, and log tail to explain or reproduce it — context that decays fast and that no incumbent (Sentry, Jam, Replay) captures for the local, git-anchored surface.
- **The moat is a deterministic set intersection.** Files on the crashing stack ∩ files changed since the last green commit, scored with fixed integer weights and zero LLM/network/randomness calls (verification: CONFIRMED). Its value is accumulated local ground truth a hosted tool cannot see and a prompt cannot reproduce.
- **Redaction is a mandatory, type-enforced gate.** `RedactedBundle` is a branded type producible only by `redact()`, so the compiler blocks any unredacted bundle from reaching a sink. The gate fails closed and is backed by a CI secret-regression corpus (verification: CONFIRMED).
- **The core pipeline is genuinely built and tested:** capture, four collectors, the green-commit journal, deterministic suspect ranking, the redaction gate, all five test-runner parsers, three sinks, and a read-only stdio MCP server with six tools.
- **MCP is the primary distribution channel by design** — the build order ships the MCP server before the GitHub issue sink, because feeding agents (not filing issues) is how the category spreads. The server is verified stdio-only, read-only, with no network or auth.
- **Adoption is individual and zero-buy-in:** `npx whatbroke run -- <cmd>`, with no install, config, account, or team rollout. The growth model is recognition and stars, not sales.
- **Positioning is complementary, not replacement,** and the wedge is a thesis under test: the spec mandates a pre-M2 validation gate to confirm incumbents do not already own the local-terminal-crash-to-brief path before further investment.

## The Problem

When a Node/TS test suite or dev server dies in the terminal, the developer who hit the crash holds context that decays by the minute and is painful to transfer. Reproducing and explaining the failure to someone else — a teammate, a GitHub issue, or, increasingly, a coding agent like Claude Code or Cursor — means manually reassembling facts scattered across the shell scrollback, the working tree, and git history.

**Who feels it, and how acute it is.** The product targets solo developers and small teams (2–20) on Node/TS projects who run suites or servers locally and then file issues or feed context to an AI agent. The pain is specific to the moment of failure: a stack trace has just scrolled past, the working tree has uncommitted edits, and the question "what changed since this last worked?" has an answer that exists only in local state. The specs frame this as a structural gap no incumbent covers — Sentry/Rollbar/Datadog watch deployed apps, Jam.dev captures browser/DOM/network bugs, and Replay.io does time-travel runtime recording. None see the local terminal/backend crash anchored to git state, and specifically none combine the uncommitted diff with a green-commit delta. This is asserted as the wedge but is explicitly subject to a pre-M2 validation gate — the team is required to confirm competitors do not already cover this path before committing further — so it should be treated as a thesis under test, not a settled fact.

**What the manual workflow costs.**

- *Time and lost context.* Today the developer hand-copies the stack trace, recalls which files they touched, eyeballs `git diff`, notes Node/package versions, and pastes a log tail — repeatedly, every crash. whatbroke's stated bar is to collapse this into a single wrapped command that, on a non-zero exit, uncaught exception, unhandled rejection, or killing signal, assembles a bundle a stranger could read and reproduce from, with under five seconds of overhead. The brief it produces is concrete: the suspect file and line, the diff since the last working commit, and the redacted error.

- *Leaked secrets.* The current copy-paste workflow has no guardrail. A log tail, an error message, or a `git diff` of a changed `.env` routinely carries AWS keys, tokens, JWTs, connection strings, or Authorization headers straight into a public issue. The specs treat a single leaked token in a public tracker as a project-killing event, and git diffs are called out as a constant leak source. The implementation backs this: redaction is a mandatory, fail-closed gate, verified as enforced (CONFIRMED), with the caveat that config can loosen the gate's strength — though never disable it. (Detailed below under Security and Trust.)

- *Aiming the fix.* For agent-assisted workflows, the cost is misdirected effort: without grounded context, an agent guesses at which file to edit. whatbroke's deterministic suspect ranking — the intersection of files on the stack trace AND changed since the last green commit (weighted +5, the marquee signal) — exists to make the agent "aim before it shoots." This ranking is verified deterministic with no LLM involvement (CONFIRMED), and the green-commit journal that powers it is verified as built and wired into both ranking and confidence scoring.

**Scope discipline as part of the problem definition.** whatbroke deliberately solves only this slice. It diagnoses and localizes the crash that just fired; it does not write fixes, monitor production, or hunt for latent bugs. That narrowness is the point: the cost being eliminated is the manual assembly and unsafe sharing of grounded crash context, not the act of fixing code, which remains the coding agent's job.

## What It Is and What It Has

The codebase is substantially built, not aspirational. The capture-to-redaction-to-sink pipeline, the green-commit journal, suspect ranking, the full redaction gate, all five test-runner parsers, the file/stdout/GitHub sinks, and the read-only MCP server all exist with passing tests.

**Capture modes.** The wrapped-process mode is built (`src/capture/runner.ts`): it spawns the child with `node:child_process.spawn`, streams raw bytes straight through to the terminal, captures bounded ring-buffer tails of stdout/stderr/combined, forwards SIGINT/SIGTERM, supports an optional `--timeout`, and classifies the exit into one of four crash kinds (`nonzero-exit`, `uncaught-exception`, `unhandled-rejection`, `signal`). The programmatic hook is partially built: `install()` and `capture()` exist in `src/index.ts`, but with two honest caveats — hook mode produces empty logs unless the caller supplies a buffer, and `capture()` hardcodes `kind='uncaught-exception'` even for manually caught errors. The spec frames full hook mode as v1.5.

**Collectors.** Four run concurrently via `Promise.allSettled` (`src/collectors/index.ts`), and a failing collector degrades to a typed fallback rather than crashing the pipeline. Env collects OS/Node/package-manager identity and env-var *keys only* (values are always `{}` at this stage). Deps reads declared versions, detects the lockfile, and resolves installed versions only for packages appearing in stack frames, capped at 20. Git collects branch/HEAD/dirty/changed-files and a working-tree-inclusive `diff vs green` through a swappable `DiffProvider` (only the `git` shell-out impl ships). The diff is byte-capped at 200 KB.

**Green-commit journal.** Built (`src/journal/journal.ts`), stored at `.whatbroke/journal.json`, keyed by a SHA-256 fingerprint of normalized argv plus branch (volatile flags like `--watch`/`--coverage` stripped so variants share a key). It records HEAD as green on exit-0 runs, is read on crash to resolve `greenRef`, self-GCs (60-day / 200-entry caps), and uses last-write-wins concurrency. A `merge-base` then `HEAD~1` fallback chain runs when no journal entry exists.

**Suspect ranking and confidence.** Built and verified LLM-free and deterministic (`src/repro/suspects.ts`, `confidence.ts`, `changed.ts`). The marquee signal is the intersection of files on the stack AND changed since green (+5); other weights are stack position (3/2/1 decaying), changed-only (+1), and `node_modules` frames (+0.5). Output is capped at 5 suspects, stably sorted. Confidence is high/medium/low driven by the same intersection. The import-graph one-hop signal (+2) is explicitly stubbed out as post-v1. Reason strings honestly say "uncommitted change" rather than "since green" when no green ref exists.

**Redaction.** A mandatory, type-enforced gate (`src/redaction/redact.ts`). `redact()` is the only producer of the branded `RedactedBundle`, and every sink and MCP reader is typed to accept only that brand, so no unredacted bundle can structurally reach an output. It is fail-closed, runs known-format detectors then env-value then denylist then an optional entropy pass, rebuilds `envValues` from an allowlist only, and emits a `RedactionReport` of rule names and hit counts that never stores the secret values. A CI corpus test asserts zero survivors across 11 known credential formats plus high-entropy values and an env secret. Config can tighten but never disable the gate. Two honest weakening knobs exist: a misconfigured `allowEnv` surfaces those values verbatim, and `entropy:false` drops the entropy pass.

**Bundle artifact.** Each crash writes two sibling files, `whatbroke-<id>.json` and `whatbroke-<id>.md`, into `.whatbroke/bundles/`. The "single self-contained bundle" framing is accurate at the logical level (one id) but is two files on disk, not one. The schema (`src/types.ts`) is versioned. The Markdown renderer (`src/render/markdown.ts`) is pure, produces a fixed section order with collapsible `<details>`, folds library frames, and always renders the redaction footer as a trust signal. `.whatbroke/` is auto-gitignored on first run (best-effort; failures are swallowed).

**CLI surface.** Six hand-rolled subcommands (`src/cli.ts`): `run` (the full pipeline, with `--out`, `--no-file`, `--md`, `--github`, `--timeout`, `--log-lines`, `--explain`, `--quiet/--verbose`), `mcp`, `show`, `open`, `journal` (`--list`/`--clear`), and `doctor`. Usage errors exit 64; the child's exit code is otherwise mirrored exactly. On a passing run whatbroke is near-transparent to the child's stdout but not silent: it writes one suppressible `✓ green recorded` line to stderr and performs journal/gitignore writes.

**MCP tools.** Built and verified read-only (`src/mcp/server.ts`, `store.ts`): stdio transport, project-scoped, no writes/network/LLM. The server serves facts as captured (carrying `git.head`) and never re-resolves paths against the working tree. The "computes nothing" claim is accurate modulo light read-time projection (sorting, one-line error summaries, log grep). Auto-registration into agent config is deferred; v1 ships copy-paste snippets.

| Tool | Returns |
| --- | --- |
| `list_bundles` | All bundles, newest first |
| `get_bundle` | A full bundle (defaults to latest) |
| `get_suspects` | Ranked suspect files with reasons |
| `get_diff_vs_green` | The diff since the last green commit |
| `get_logs` | Captured log tail, with optional grep |
| `get_repro` | Reproduction steps with provenance tiers |

Three mirroring resources accompany the tools, all defaulting to the latest crash.

**Sinks.** Three are built: file (default), stdout-markdown (`--md`), and GitHub issue (`--github`). The GitHub sink prefers `gh issue create --body-file`, falls back to a length-capped prefilled URL, infers the repo from the origin remote, and never throws. Linear/GitLab are out of scope for v1.

**Config.** Layered resolution (`src/config.ts`): defaults < user home < project < CLI flags. The schema has no field that could disable redaction, only `allowEnv`/`denyPatterns`/`entropy`. `defaultSink` is typed as the literal `'file'`. Malformed config files are silently skipped.

**Provenance and narration.** Provenance tiers (`observed`/`derived`/`heuristic`) exist but apply *only to repro steps*, not to "every fact" — crash, env, deps, git, logs, and suspects carry no tier (the README's universal framing overstates this). LLM narration is opt-in behind `--explain`, off by default, and structurally cannot alter steps, suspects, or confidence.

**Planned, not built.** The VS Code extension (read-only viewer) is documented but absent from the codebase. Source-map resolution, the import-graph hop, preceding-command hints, full programmatic-hook log capture, and non-Node languages are all explicitly post-v1.

## How It Works (Architecture and Pipeline)

The architecture is a five-stage pipeline of pure-ish functions — CLI → Capture → Collectors → Repro Reconstruction → Redaction Gate → Sinks/Readers — with the only persistent state being a project-local journal file. Each stage takes an explicit typed input and produces an explicit typed output, which makes the whole thing unit-testable with synthetic data and lets the CLI, MCP server, and (post-v1) VS Code extension evolve independently against one schema.

### The wrapper and capture

You invoke `whatbroke run -- <command> [args...]`; everything after `--` is the verbatim child command. `runCommand` (`src/capture/runner.ts`) spawns it, inherits stdin, and pipes stdout/stderr. Raw child bytes are forwarded to the parent terminal in real time, so on the happy path the developer sees exactly the output they would without whatbroke, and the wrapped command's exit code is mirrored back. Output is teed into three bounded `RingBuffer` instances (stdout, stderr, and a combined interleaved view), defaulting to the last 500 lines per stream, capping memory regardless of how chatty the process is and setting a `truncated` flag when lines are evicted. Per-stream `StringDecoder`s reassemble multibyte characters split across chunks, and a binary-output heuristic flags non-UTF8 streams instead of corrupting the buffer.

On exit, `classifyCrash` (`src/capture/classify.ts`) decides what happened: exit 0 with no signal returns `null`, otherwise it emits a `CrashSignal`. Signal termination always wins classification; non-signal exits are upgraded by scanning the stderr tail for Node's rejection/exception markers. Spawn failures such as a missing binary (`ENOENT`) are surfaced as a usage error with exit code 64, distinct from a real child crash — no bundle is produced.

A note on the "invisible wrapper" framing: it is accurate for the child's stdout and exit code, but a passing run is not a no-op. On exit 0, `runCmd` writes a single dim `✓ green recorded` line to stderr (suppressible with `--quiet`), ensures `.whatbroke/` is gitignored, and records a green journal entry. These side effects are deliberate — the green half is what powers suspect ranking.

### Git-anchored context collection

When a crash fires, `collectAll` runs three collectors concurrently via `Promise.allSettled`: environment, dependencies, and git. The contract is graceful degradation — a collector that fails substitutes a typed empty value and records a `{ collector, error }` entry; it never aborts the bundle. Test-runner detection runs synchronously after that phase.

- **Environment** (`env.ts`) captures OS, Node/V8 versions, and the package manager. It records environment-variable **keys only**; `envValues` is always empty here, with values restored later only for an allowlist — privacy-by-design split.
- **Dependencies** (`deps.ts`) resolves installed versions only for packages that actually appear in stack-frame paths, capped at 20 — high signal instead of a full tree dump.
- **Git** (`git.ts`) is where the moat lives. It reads branch, HEAD, dirty status, and changed files from `git status --porcelain`, then resolves the "green" baseline via a strict chain: the journal first, then `merge-base` against origin/main/master, then `HEAD~1`, then none. With a green ref it produces `diffVsGreen` through a swappable `DiffProvider` (the v1 impl shells out to `git diff <ref>` against the working tree, so it captures uncommitted edits) capped at ~200 KB.

The **green-commit journal** (`src/journal/journal.ts`) persists to `.whatbroke/journal.json`, keyed by a SHA-256 fingerprint of normalized argv plus branch, with volatile flags stripped so `npm test` and `npm test --watch` share one entry. Each value stores `{ greenSha, greenAt, runCount }`. It self-GCs, tolerates corrupt/missing files by falling back to empty, and persists atomically via temp-file-then-rename. Concurrency is last-write-wins — a documented v1 trade-off, treating the journal as a heuristic cache rather than a source of truth.

### Deterministic suspect ranking and confidence

`reconstruct` (`src/repro/reconstruct.ts`) assembles a `ReproInfo` from the crash and context with no LLM in the loop. It emits steps in a fixed six-slot order (git state, delta vs green, environment, the action, observed result, first app frame), omitting any slot whose inputs are absent, and tags each step with a provenance tier. It never leaks absolute paths and excludes whatbroke's own footprint from changed-file accounting.

Ranking and confidence both derive their changed-file set from one shared function, `changedSinceGreen` (`src/repro/changed.ts`), so the two subsystems can never disagree about the marquee intersection. `rankSuspects` scores candidates with fixed integer weights: a file that is **both on the stack and changed since green** gets +5 (the marquee signal); top user frame +3 decaying by one per subsequent user frame with a floor of 1; changed-only +1; a `node_modules` frame +0.5. Output is sorted by descending score with a stable alphabetical tie-break and capped at five suspects, each carrying a `reasons[]` array. `computeConfidence` returns `high` when user-code stack files intersect the changed set, `medium` with a green ref and a user frame but no intersection, and `low` otherwise. Tests assert byte-for-byte deterministic output across repeated runs. The one acknowledged gap: the import-graph one-hop signal (+2) is intentionally unimplemented in v1. And the changed-file set is a union of committed diff-vs-green plus uncommitted working-tree changes; with no green ref it falls back to uncommitted-only and labels suspects "uncommitted change" rather than "since green."

### The redaction gate

The assembled `Bundle` is pre-redaction and never touches a sink. `redact()` (`src/redaction/redact.ts`) is the **sole producer** of the branded `RedactedBundle` type, and every sink and reader is typed to accept only that brand — so routing an unredacted bundle to any output is a compile-time error, not a convention. `redact()` deep-clones the input, then runs a layered detector chain over every free-text field: ten known-format detectors (AWS, GitHub, Google, Slack tokens, JWTs, PEM blocks, connection strings, auth/bearer headers), an env-value detector, a config-supplied denylist, and a final high-entropy pass. `environment.envValues` is rebuilt from scratch, restoring only allowlisted keys. The gate **fails closed**: if a field's redaction throws, the field is dropped and replaced with `‹redacted:error›`. A `RedactionReport` records rule names and hit counts but never the matched values, and is always rendered in the Markdown footer. The corpus test seeds 12 real-shaped credential formats and asserts zero survivors anywhere in the serialized bundle.

Config can tighten but never disable the gate — there is simply no field to turn it off. Two knobs tune its strength downward without disabling it: `allowEnv` surfaces allowlisted env values verbatim (a misconfigured allowlist can leak), and `entropy: false` drops the final pass while the higher-precision detectors still run.

### Delivery: push sinks and pull readers

**Sinks** run synchronously at the end of `run` and receive the `RedactedBundle` in memory: the file sink (default) writes the JSON plus rendered Markdown into `.whatbroke/bundles/`; the stdout-markdown sink (`--md`); and the GitHub issue sink (`--github`), which prefers the `gh` CLI with a `--body-file` and falls back to a length-capped prefilled URL. The Markdown renderer is a pure function with no I/O and no redaction of its own.

**Readers** are out-of-process, read-only, and only ever touch already-gated JSON on disk. The primary v1 delivery surface is the **MCP server** (`whatbroke mcp`), stdio-only and project-scoped, with no network, auth, or account. The redaction guarantee holds for free because only post-gate bundles are ever persisted; the server computes nothing, mutates nothing, and makes no LLM call. It performs read-time shaping (newest-first sort, a one-line error summary, optional case-insensitive grep on already-redacted logs) and deliberately reports file paths paired with the bundle's captured `git.head` rather than re-resolving against a moved working tree, making staleness explicit. One structural caveat: readers cast on-disk JSON straight to `RedactedBundle` without re-validating, trusting the write side — sound because `redact()` is the only producer, but a hand-placed file would be trusted unverified.

## The Moat and Why Deterministic

The defensible core of whatbroke is a single, cheap computation: the intersection of files **on the crashing stack** with files **changed since the last green commit**. This is not a model output. It is set arithmetic over two sources of local ground truth that no hosted service can see, and it is the one signal the specs call "the thing nobody packages."

**How the signal is computed.** The green-commit journal is the accumulating half. On every passing run, `runCmd` records the current HEAD as the last-known-good commit, keyed by a fingerprint of the normalized command plus branch. The fingerprint strips volatile flags so `npm test` and `npm test --watch` resolve to the same green SHA. The journal lives at `.whatbroke/journal.json`, is gitignored, self-GCs, and degrades to empty on corruption — purely local, per-clone, per-developer state that gets more valuable the more you use the tool. On a crash, `collectGit` resolves the green ref (journal first, then `merge-base HEAD origin/main`, then `HEAD~1`) and produces a working-tree-inclusive `diffVsGreen`. `changedSinceGreen` then unions the porcelain working-tree changes with the diff paths into one set, and `rankSuspects` scores any file that is both on the stack and in that set with the dominant weight.

**Why "deterministic" is load-bearing, and verified.** Adversarial code-verification **confirms** the no-LLM claim: across `src/repro/*.ts` there are no LLM, network, randomness, or clock calls — only fixed integer weights and a stable sort. A determinism test asserts the same input yields byte-identical output twice. This matters competitively because it is exactly what a prompt cannot reproduce: an LLM has no access to your journal of past green commits and no deterministic way to recompute the intersection. A "pipe the stack trace to GPT" wrapper is a weekend clone; the journal-crossed-with-stack signal is not, because it depends on accumulated local history the model never sees.

The redaction gate is the second structural guarantee, also **confirmed**: `RedactedBundle` is a branded type whose only producer is `redact()`, every sink is typed to accept only that brand, and redaction fails closed. This is what makes the ground-truth context shareable into a public issue or an agent without leaking secrets — the moat is only useful if the bundle is safe to hand off, and the gate makes that a property of the type system rather than a convention.

The strategic consequence is consistent with the code: SaaS incumbents sit at production, runtime-replay, or browser surfaces and structurally cannot observe the local terminal crash plus the uncommitted working-tree diff plus the green-commit delta. That triad is computed entirely on-disk, with no backend and no model, and that is precisely why it is defensible.

## Why It Is Better Than What Exists

whatbroke does not try to beat the incumbents at their own game. It occupies a surface none of them own: the local terminal/backend crash, anchored to git state, delivered to a coding agent. The positioning is explicitly complementary — "works alongside Sentry/Jam; fills the local-terminal gap they don't."

| Incumbent | What it owns | Where it stops |
| --- | --- | --- |
| Sentry / Rollbar / Datadog | Deployed-app monitoring: errors from production/staging, dashboards, alerting, release tracking | No visibility into the test suite or dev server dying in a shell; structurally cannot see the uncommitted working tree |
| Replay.io | Time-travel runtime replay: a recorded, re-executable session | A different mechanism entirely; whatbroke records nothing, it packages observed facts at crash time |
| Jam.dev | Browser bug capture (DOM, network, console) via a Chrome extension | A frontend/QA surface; whatbroke is deliberately terminal/backend, not the browser |
| Cursor / Claude Code | LLM-based code *fixing* | whatbroke does not generate or fix code (verified LLM-free); it makes the fixing agent "aim before it shoots" with grounded, ranked context over MCP |

**The gap none of them fill — and whatbroke's wedge.** The unowned territory is a local crash, plus the diff since the last *green* commit, plus a deterministic ranking of the suspect file. This is real in the code, not just the spec: a per-command, per-branch green-commit journal (CONFIRMED: `src/journal/journal.ts`, `src/commands/run.ts`, `src/collectors/git.ts`), and a marquee suspect signal that is the deterministic intersection of files on the stack and files changed since green, scored highest (+5) by fixed integer weights with no model in the loop (CONFIRMED: `src/repro/suspects.ts`, `changed.ts`). This data is structurally invisible to the incumbents: Sentry sees production, not your dirty working tree; Jam sees the browser, not your test runner; Replay records a session rather than diffing against git; and a raw LLM has no green-commit history to intersect against.

**Honest scoping of the differentiators.** Two refinements keep the claims grounded. First, the "changed since green" set is a *union* of committed diff-vs-green and uncommitted working-tree changes; when no green ref exists it falls back to merge-base / HEAD~1 and labels suspects "uncommitted change." The intersection signal still runs, but the strongest framing depends on a populated journal — which is why the spec mandates a pre-M2 validation gate before further investment. Second, MCP delivery is the distribution mechanism, not the moat: the spec itself calls MCP "table stakes for the category" (CONFIRMED read-only stdio with no compute: `src/mcp/server.ts`, `store.ts`). The defensibility is the ranked, git-anchored context — MCP is just the wire that carries it to the agent.

## Security and Trust Posture

whatbroke's security model starts from a single premise: a single leaked token in a public issue is a project-killing event. That threat — not a generic privacy nicety — drives the design. The bundle's whole reason to exist is to be shared, so redaction is treated as a first-class gate.

**A mandatory gate enforced by the type system.** `RedactedBundle` is a branded type (`Bundle & Redacted`, with a phantom `unique symbol`), and `redact()` is the only function that produces it. Every sink is typed `(bundle: RedactedBundle) => Promise<SinkResult>`, so the compiler rejects any attempt to route a raw `Bundle` to an output. Both write paths confirm this in practice: the crash path assembles, then redacts, then constructs sinks; the programmatic `capture()` redacts before any file is written or returned. The gate fails *closed*: each field scrub is wrapped in try/catch, and on any detector error the field content is dropped and replaced with `‹redacted:error›`. The corpus test seeds twelve real-shaped credential formats plus arbitrary high-entropy env values across every free-text field and asserts zero survivors, with CI failing on any leak.

**Tighten, never disable.** The configuration schema is deliberately incapable of turning the gate off. `WhatbrokeConfig.redaction` exposes only `allowEnv`, `denyPatterns`, and `entropy`, and `RedactOptions` has no disable field — an architectural guarantee, not a checked one. Config can only *add* rules; invalid patterns are silently skipped so a bad entry can never throw the pipeline or weaken other rules. Two honest caveats apply and should be documented for users: `entropy: false` drops only the lowest-precision pass (the high-value known-format, env-value, and denylist detectors still run), and `allowEnv` surfaces those keys' values verbatim and exempts them from the env-value detector — a misconfigured allowlist is the one way a user can cause a secret env value to appear un-scrubbed. The gate cannot be removed; its strength is partly tunable downward.

**The redaction report as a trust signal.** Every rendered bundle ends with an always-visible footer (never collapsed into `<details>`): "No secrets detected" when nothing fired, otherwise the count and the names of the rules that hit. The report stores only rule names and hit counts — never the matched values, even in debug mode — and a test asserts the report body contains no raw secret text. This is what makes pasting a bundle into a public tracker a defensible action rather than a leap of faith.

**Local-only, no account.** There is no backend, no dashboard, and no account anywhere in the design or the code. Bundles are written to `./.whatbroke/bundles/`, which whatbroke auto-appends to `.gitignore` on first run so artifacts and the journal never get committed; gitignore writes are best-effort and never abort a run. Secrets never leave the machine.

**MCP read-only, inheriting the guarantee.** The MCP server is stdio-only — a local child process with no HTTP, network, auth, or account. `BundleStore` imports only `readdir`/`readFile` (no write/exec/network calls in production code), and the only data on disk is post-gate `RedactedBundle` JSON, so the server never sees pre-gate data. One implementation note: readers cast disk JSON straight to `RedactedBundle` with only a minimal structural check, trusting the write-side invariant rather than re-redacting. That is sound precisely because `redact()` is the sole producer and always runs before persistence — but a bundle hand-placed on disk would be trusted unverified.

## Target User and Adoption Path

**Who adopts it.** The target user is narrow and deliberate: solo developers and small teams (2–20) on Node/TS projects who run test suites or dev servers locally and file issues on GitHub/GitLab/Linear. v1 is Node/TS only — the spec is firm that the Node path must be "sharp" before any generalization. The wedge is the local terminal/backend crash anchored to git state: a server or test suite dying in the shell, not a browser session (Jam's lane), not production (Sentry/Datadog's lane), and not time-travel replay (Replay.io's lane). The Playwright parser is the one nod toward frontend/e2e authors, but the center of gravity is backend and test-running Node developers who hand crash context to a coding agent.

**How they adopt it: individual, zero team buy-in.** Adoption is structurally individual. The entry point is a single wrapped command with no install and no configuration: `npx whatbroke run -- npm test`. No backend, no dashboard, no account, no team rollout. A developer wraps a command they already run; on a passing run the tool records the current commit as last-known-good and otherwise stays out of the way, and on a crash it writes a redacted bundle to `.whatbroke/`. The first-run UX auto-creates the directory and appends it to `.gitignore`, so nothing leaks into the repo and no teammate has to agree to anything. The bet is that wrapping one command clears the bar that a team-wide tool never would.

One honesty caveat surfaced by verification: "invisible on the happy path" is slightly overstated. On a passing non-quiet run, whatbroke emits a single stderr line (`✓ green recorded (<sha>)`) and performs two side effects — the `.gitignore` write and the green-journal entry. These go to stderr only, never touch the child's stdout, and the notice is suppressible with `--quiet`. The wrapper is transparent to the child's output and exit code, but it is not a literal silent no-op.

**The one-screenshot demo.** The spec sets a hard legibility bar: the demo must be readable in one screenshot or short clip, and "if the demo needs explaining, scope is wrong." The concrete v1 demo is a 20–30s loop: a command crashes, a coding agent is asked to "fix the failing test," it calls `get_suspects` over MCP, receives the correct top suspect plus the diff since last green, and edits the right file. What makes that land in one frame is verified in the code: suspect ranking is deterministic and grounded, not LLM guesswork, with byte-identical output across runs asserted by test. Note the "names the right file" promise (top-3 for a majority of "edited code broke a test" cases) is a **spec target the spec itself says to "measure it" — there is no benchmark, dataset, or measured hit-rate in the repo yet.** It rests on a real, model-free signal (the part the Reddit draft calls "the one part I haven't seen elsewhere"), but as of now it is a claim about mechanism, not an evidenced result.

**Distribution: MCP as the primary channel; stars as the model.** MCP-into-agents (Claude Code, Cursor) is the primary delivery surface and the primary distribution channel for the category — "table stakes, not a bonus." The build order encodes this by sequencing the MCP server (M3.5) before the GitHub issue sink (M6): the agent feed ships first because feeding agents is how the tool spreads. Code verification confirms the server is exactly as scoped — stdio-only, project-scoped, read-only, six read tools, no network, no auth, no account, no LLM. That tight surface is itself an adoption argument: nothing to provision, nothing to trust beyond a local child process.

The distribution *model* is recognition and stars, not sales. There is no backend to monetize and no account to convert; the launch artifacts (MIT license, README with the demo clip, npx quickstart, positioning statement, moat explanation) and staged Reddit validation in r/node and r/javascript are aimed at developer word-of-mouth. The VS Code extension is explicitly classified post-v1 as a "recognition/demo play, not a moat play." The moat lives in the CLI plus MCP — the green-commit journal × stack-trace intersection, which verification confirms is built and which competitors structurally cannot see.

## Long-Run Impact and Vision

**The bet.** whatbroke is a bet on a specific second-order effect of AI writing more code: as generation gets cheaper, the bottleneck moves from *producing* a fix to *localizing* the failure and handing an agent enough grounded context to fix the right thing. The product's thesis is that this localization step belongs in the terminal, anchored to git state, with the answer flowing to the agent over MCP rather than to a human over a dashboard. The specs back this with sequencing, not just rhetoric: the MCP stdio server is deliberately built *before* the GitHub issue sink because "MCP-into-agents is the primary distribution channel for the category." The agent — not the developer pasting snippets — is the first-class consumer.

That bet is structurally coherent in the code that exists today. The defensible core is the green-commit journal crossed with the stack trace, a deterministic suspect-ranking signal verified genuinely LLM-free and deterministic (no `Math.random`, `Date.now`, or model calls in `src/repro/`; determinism asserted by test). The journal accumulates per-command "last known good" SHAs locally — ground truth a SaaS monitoring tool watching production never sees.

**Where it can go.** The expansion path is constrained by design, which is the point.

- **More sinks.** The `Sink` type is `(bundle: RedactedBundle) => Promise<SinkResult>`, and file/stdout/GitHub sinks already conform. Linear and GitLab sinks (named v2) are purely additive — no core change required.
- **Other test runners and diff backends.** Five runners ship behind a pluggable parser array; adding one is local. The `DiffProvider` interface isolates git so a structural/language-aware diff engine can be swapped in at one file.
- **Other languages.** This is the largest growth lever and the least de-risked. v1 is explicitly Node/TS only, and the entire capture and parsing layer is V8/Node-specific: stack parsing keys on `at fn (file:line:col)`, crash classification scans for `UnhandledPromiseRejection`, and the unhandled-rejection detector matches Node's stderr text markers (e.g. `UnhandledPromiseRejection`), which a test comment treats as a stable contract but which is in fact version-brittle. A Python or Go port re-implements capture, classification, and stack parsing from scratch. The journal × diff intersection — the actual moat — is language-agnostic, but reaching it in a new language means rebuilding the front half of the pipeline. Multi-language is a credible second act, not a quick fan-out.

**The realistic ceiling.** whatbroke is a focused, single-job developer utility, not a platform. The realistic outcome is a well-regarded, possibly category-defining open-source CLI that becomes the default way Node developers feed crash context to coding agents — valuable, defensible for as long as the local-terminal gap stays open, and naturally complementary to Sentry/Jam/Replay. Its ceiling is bounded by three things it cannot fully control: how fast incumbents close the wedge, whether multi-language reach materializes before that happens, and whether the no-backend, no-account, purely-local model (its trust advantage) also caps its ability to compound network or data effects. There is no recurring-revenue surface here by design — a deliberate trade of a smaller addressable ceiling for a moat that prompting cannot clone.

### Honest Risks and Open Questions

- **The wedge is a timing bet, gated before M2.** The dominant 2026 strategy across Sentry, Replay, and Jam is "shifting left into local dev and delivering answers via agents + MCP." If any of them ships a local CLI that captures the working-tree diff and green delta, the wedge closes. The spec mandates a non-code validation gate before M2 to confirm incumbents do not already own this path — and to reassess the whole product if they do. The entire positioning and adoption story assumes that gate passes.
- **Redaction strength is partly tunable downward (verification caveat on a CONFIRMED gate).** The gate is enforced well and fails closed, but `allowEnv` surfaces those env *values* verbatim and `entropy:false` drops the high-entropy pass entirely. One leaked token in one public issue would do disproportionate reputational damage to a tool whose whole pitch is "safe to share." These knobs should be documented prominently.
- **Provenance is narrower than advertised (PARTIAL).** The spec frames "every fact carries a provenance tier," but the tier exists only on repro steps. Crash details, environment, deps, git state, logs, stack frames, and ranked suspects carry no tier. Trust is explicit where heuristics are most likely to masquerade as fact, but the universal claim is overstated.
- **"Single self-contained bundle" is two files (PARTIAL).** Each crash writes a sibling `.json` and `.md`. "Single bundle" holds at the logical level (one id), but the on-disk output is not one self-contained file.
- **"Invisible on the happy path" is overstated (PARTIAL on the transparent-wrapper claim).** A passing non-quiet run emits one `✓ green recorded` stderr line and performs `.gitignore` and journal writes. The wrapper is transparent to the child's stdout and exit code, but it is not a literal no-op.
- **The moat sharpens with the journal rather than strictly requiring it.** The journal is a last-write-wins cache (one green SHA per command+branch fingerprint), and `greenRef` falls back to merge-base/HEAD~1, so suspect ranking still runs without a journal entry — just labeled "uncommitted change" and capped at lower confidence. The marquee "since green" framing depends on a populated journal.
- **Read-side trust is unverified by construction.** Readers cast on-disk JSON straight to `RedactedBundle` without re-redacting, trusting the write-side invariant. Sound while `redact()` is the sole producer, but a hand-placed file would be trusted unverified.
- **Anti-scope drift is the self-inflicted risk.** The product is defined as much by what it refuses to do — no code generation, no production monitoring, no latent-bug scanning. Every adjacent feature that would broaden appeal also moves it into a lane a funded incumbent owns better. The anti-scope test is a hard gate; discipline here is the difference between a sharp tool and a diluted one.
